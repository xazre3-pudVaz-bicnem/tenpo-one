# v0.4.1 NATIVE BACK OFFICE HARDENING 完了報告

目的: **freee / KING OF TIME等の外部SaaSなしで、TENPO ONE内部だけで日常業務が一周する**ことを実データで検証し、不整合を修正した。

最重要完成条件の検証結果:

> POSで売上を作り、スタッフが働き、仕入や経費を登録したら、TENPO ONE内部だけで
> 売上 → 在庫 → 原価 → 勤怠 → 給与 → 仕訳 → P/L までつながる

→ `scripts/verify-backoffice.mjs`（新規・54チェック）と既存 `scripts/verify-flow.mjs`（103チェック）で
**実Supabase・実ユーザーログイン（RLS適用）のもと全項目GREEN**を確認済み。

## 1. 会計フロー（検証済み）

```
POS会計（finalize_order）
  → payments（現金/キャッシュレス別・8%/10%別）
  → 自動仕訳（/app/accounting/auto、日次・店舗別に集計）
      現金売上:     借方 現金100    / 貸方 売上高400・売上高軽減401
      キャッシュレス: 借方 売掛金130 / 貸方 売上高400・401
  → 仕訳帳（/app/accounting） → 総勘定元帳（/app/accounting/ledger）
  → 試算表・P/L・B/S（/app/accounting/statements） → 本社ダッシュボード
```

- 仕入: 仕入高500/買掛金200 → 支払で 買掛金200/普通預金110（消込）
- 経費: 費目/現金・小口・預金・未払（paidVia別）
- 小口現金: 精算時に費目/小口現金101
- 給与: 給与手当510/未払費用211（確定時）
- 銀行入金: 普通預金110/売掛金130（売掛消込）

**二重生成防止**: `journal_entries.source_type + source_id` による冪等生成（sales=`{storeId}:{date}`、他=元行id）。
CASE1で同一sourceの仕訳が1件のみであることを実DB確認。

**双方向トレース**: 仕訳一覧は `?source_type=X&source_id=Y` で絞り込み可能。
仕訳→元取引（注文/経費/請求書/給与run/銀行取引）、元取引→仕訳（「仕訳を見る」リンク）を実装。
自動/手動仕訳のバッジ表示。

## 2. 帳簿・財務諸表

- **総勘定元帳**: 科目選択→日付・摘要・**相手科目**（複数は「諸口」）・借方・貸方・**残高**（期首から積上）・店舗・元取引。期間/店舗指定・CSV。
- **試算表**: 期首残高・借方合計・貸方合計・期末残高の4列（`aggregateTrialBalanceWithOpening`）。
  借方合計≠貸方合計は danger 表示で異常検知。各セル→元帳ドリルダウン。
- **P/L（段階損益）**: 売上高 −売上原価(500-509) ＝売上総利益 −人件費(510-519) −経費 ＝営業利益
  （`buildOperatingStatement`）。全社/店舗別・月別・前月/前年同月比較。
- **B/S**: 資産＝負債＋純資産＋当期純利益 のチェック。不一致時は管理者向け警告バナー。

## 3. 月次締め

- 締め前=修正可 / 締め後=`PERIOD_CLOSED`（DB RPCで強制）→ CASE6で実証。
- 解除は org_owner/hq_admin のみ・**理由必須**（`REASON_REQUIRED`）→ audit_logsへ記録 → 修正 → 再締め → CASE7で実証。
- 12ヶ月一覧（状態・締め実行者・解除履歴・下書き残数）・締め/解除のaudit履歴表示。
- **確定仕訳の物理削除をDB層で禁止**（migration 00023/00024）: posted/voidedの仕訳・明細は
  service roleでも削除不可（`JOURNAL_IMMUTABLE`）。修正経路は修正仕訳とvoid（監査ログ付き）のみ。
  ※検証エージェントが発見した「RLS書込ロールがRPCを介さず物理削除できる」穴を塞いだもの。

## 4. 銀行CSV（API不要運用）

- CSV取込: `import_hash`（日付|摘要|入金|出金のsha256）で完全重複を自動スキップ。
- **疑わしい重複**（同日同額・摘要違い）は取込前プレビューで警告し、行ごとに取込/スキップを利用者が選択。
- 取込結果サマリ（新規N・完全重複スキップN・要確認M件取込）。
- 入出金→仕訳候補→人が確認→確定。売掛回収/買掛支払の消込ショートカット付き。冪等（journal_entry_id設定済みはスキップ）。

## 5. 給与フロー（勤怠→給与、再入力ゼロ）

```
シフト → 打刻（出勤/休憩/退勤・状態機械） → 勤怠
  → 給与run作成（期間の time_entries を自動集計・再入力なし）
  → 計算根拠付きプレビュー（適用時給×時間・残業/深夜×割増・歩合=売上×料率・交通費）
  → 承認 → 確定（approved）
      ・使用ルールのsnapshotを payroll_runs.rules_snapshot に保存
      ・以後 payroll_items はDBトリガーで変更不可（PAYROLL_RUN_LOCKED）→ CASE8で実証
  → 給与明細（本人閲覧・印刷） → 給与仕訳（給与手当/未払費用） → P/L人件費
```

- **確定の不変性**: 確定後に時給・歩合率・法定ルールを変えても過去runは変わらない
  （snapshot + DBトリガー + 再計算アクションの拒否）。
- **計算根拠**: payroll_items.breakdown に日別・ルール期間別・歩合ルール別の内訳（単価・料率・時間・売上額）。
- 賞与は別run（run_type='bonus'）。

## 6. 本人領域・申請フロー

- 一般スタッフは自分のシフト・勤怠・有給・給与明細・申請のみ（RLS + UI）。他人の給与はURL直打ちでも0件（CASE9）。
- **有給**: 付与→残数→申請（全休/半休・同日重複はDB UNIQUE拒否）→承認（time_entriesへleave_fraction付与・紐付け）→残数減少。
  付与ルールはhardcodeせず leave_policy 設定。時間休はhours列の構造のみ（「今後対応」表示）。
- **勤怠締め**: 給与確定期間はスタッフ変更不可 → 「修正申請」（attendance_correction_requests）→ 管理者承認 →
  runがdraft/confirmedなら勤怠修正+再計算案内、approvedなら「確定給与は変わらない・次回給与で調整」を明示（勝手に書き換えない）。
  申請/承認/却下はaudit記録。

## 7. 法定ルール管理（/admin/legal-rules・CYPRESS専用）

- 区分: 所得税・健康保険・厚生年金・介護保険・雇用保険・割増率・その他。
- 必須項目: 年度・適用開始/終了日・version・**根拠（basis）・確認者・確認日**（migration 00022で追加）。
- 状態遷移を**DBトリガーで強制**: draft→reviewed（根拠・確認者・確認日必須）→active（activated_by/at自動記録）→superseded。
  activeへはreviewed経由必須（draft→active直行は`INVALID_STATUS_TRANSITION`）。CASE12で全遷移を実証。
- active後のparameters変更は`ACTIVE_RULE_IMMUTABLE`（変更は新version）。有効化は`legal_rule.activate`としてaudit記録。
- 一般企業ユーザーは閲覧のみ・編集不可（RLS + UI。CASE12でRLS拒否を実証）。
- **専門家レビュー用画面** `/admin/legal-rules/review`: ルール・年度・現在値・根拠・状態・確認者・最終更新の一覧。
  CSV出力・印刷（PDF保存）対応。ソースコードを見せずに税理士・社労士へ値だけ確認してもらうための資料。
- **投入済みは消費税10%/8%のみ。所得税・社会保険等の数値は未投入**（推測投入は行っていない）。
  該当画面は「試算（法定ルール確認前）」表示を維持。active+reviewedルールが投入されれば表示を外せる構造。

## 8. 数字の共通化（KPI統一定義）

読み取り監査で16件の定義齟齬を検出。今回の統一定義:

> **売上・会計件数・客数・客単価は「paid（会計成立）」の注文のみを母集団とする。**
> 返金済み(refunded)は返金額・アラートとして別掲。

修正済み（ダッシュボード・レポート・予算・日報・CSVエクスポート2本を同一定義に統一）:
- 会計件数・客数の返金込み/抜きが画面ごとにバラバラ → paidのみに統一
- ダッシュボード前月比クエリの条件非対称（当月=paid+refunded/前月=paidのみ）→ 対称化
- **月別損益推移の原価クエリに`menu_items(cost)`が欠落**（レシピ未登録商品の原価が月別表だけ抜ける実バグ）→ 修正
- KPI「利益率」の実体が粗利率だった → **「粗利率」に正名**（人件費・経費を含まない旨を注記）
- 日報生成の payroll_rules クエリに organization_id フィルタ欠落 → 追加

## 11. 専門家確認が必要な項目（値は未投入のまま）

`/admin/legal-rules/review` を印刷/CSVで渡して確認を受ける前提。

1. 所得税（源泉徴収税額表）
2. 健康保険・介護保険料率（都道府県別）
3. 厚生年金保険料率・標準報酬月額等級
4. 雇用保険料率
5. 割増賃金率（残業・深夜・休日。現在の1.25等は「試算」表示のまま）
6. 有給付与日数の法定テーブル（現在は企業設定のメモ+手動付与）
7. 減価償却（耐用年数・償却方法の適用ルール）
8. 消費税の申告様式・端数処理の確認（税率10%/8%は投入済み・version管理）

確認完了後: `/admin/legal-rules` で status='reviewed'→'active' 化 → 計算エンジンをactive参照に接続。
**それまで「正式対応済み」表示は一切行わない。**

## 12. 残課題（既知の設計判断・要検討）

監査で検出したが、影響範囲・プロダクト判断を要するため今回は修正せず記録:

1. `daily_closings.sales_total` が refunded を含む（レジ締め後の返金は再計算されない）。店舗ダッシュボードの30日推移のみこれを参照
2. **部分返金**が売上・客数から控除されない（`orders.total`不変・status=paidのまま）。返金はrefund_total/アラートにのみ現れる
3. 支払方法別内訳（payments）は返金を差し引かないため、返金日には内訳合計＞売上
4. 原価は理論原価（レシピ×平均仕入単価）。廃棄・棚卸差異は原価に含めず別掲 → 実際原価との照合は月次で `/app/accounting/statements` の仕入高と比較する運用
5. 人件費概算（ダッシュボード等）は月給÷21日の日割り・割増なし。給与モジュールの本計算とは別物（画面に注記済み）
6. `guest_count` 既定1名（テイクアウト/QRも1名）→ 業態によって客単価が歪む
7. 予算「全社行なし時のフォールバック」（店舗合算）はダッシュボードのみ。予算画面は「—」表示
8. 複数レジ店舗の daily_closings.cash_difference が最終レジで上書き（v0.3から継続）
9. 旧 `attendance_requests` テーブルは新 `attendance_correction_requests` へ移行済み。旧テーブルの残pending行があれば手動移行が必要（デモには実質なし）

8. 運用訓練: 月次締めフロー（締め→翌月）と日次の自動仕訳確定を業務手順に組み込む
