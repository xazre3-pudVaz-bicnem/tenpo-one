# 実店舗パイロット第1号 導入チェックリスト

TENPO ONEを実際の店舗へ初めて導入するときの確認リストです。
エンジニアでなくても進められるよう、画面の場所と「何を確認するか」だけを書いています。
（チェックボックスを印刷またはコピーして使ってください）

---

## 導入前（1〜2週間前）

### 契約・環境
- [ ] 企業アカウントが作成され、オーナーがログインできる
- [ ] 導入する店舗が登録されている（設定 → 店舗情報）
- [ ] 本番URLでログインできることを店長・スタッフ各自が確認

### 基本設定（設定 → 各メニュー）
- [ ] 企業情報（会社名・住所・請求情報）
- [ ] 営業時間・定休日（**深夜営業の店舗は営業日の切替時刻も確認**。例: 朝5時切替なら深夜1時の会計は前日の売上になります）
- [ ] フロア・テーブル（実際の卓数・席数と一致しているか）
- [ ] メニュー（全商品・価格・税率8%/10%の区分。売切にできるかも試す）
- [ ] 食材・在庫品目（重要な食材だけでも初期在庫数を入れる）
- [ ] レシピ・原価（主力商品だけでも。原価が出ない商品は原価レポートから除外されます）
- [ ] 予約設定（枠の間隔・受付期間・キャンセル期限）
- [ ] 会員・ポイント（使う場合のみ。付与率の設定）
- [ ] 税率・レシート表記（インボイス登録番号）

### スタッフ・給与
- [ ] スタッフ全員のアカウント作成と権限（店長/社員/アルバイト）
- [ ] 共用端末で使う場合はPIN打刻の動作確認
- [ ] 給与ルール（時給・月給・交通費）。**給与・税の法定計算は「試算」です。
      正式な給与計算は社労士・税理士の確認が終わるまで既存の方法と並行してください**
- [ ] シフトを1週間分入れてみる

### レジ・支払
- [ ] レジの登録（複数レジがある場合はすべて。例: レジ01・レジ02・テイクアウト）
- [ ] 支払方法の確認（現金・カード・QR・電子マネー・商品券・その他）
- [ ] **カード・QR決済の実際の決済は決済端末側で行い、TENPO ONEには金額を記録する運用**
      であることを店長に説明（Stripe実端末連携は未接続）
- [ ] レシートプリンターは現在シミュレーション表示（実機印刷は未接続）。
      紙レシートが必要な場合の代替運用（手書き・既存レジ併用）を決める

### QRオーダー（使う場合）
- [ ] 各テーブルのQRコードを発行・印刷
- [ ] スマホで実際に注文→キッチンに表示→会計まで通しで1回テスト

### リハーサル（導入前に必ず1回）
- [ ] 閉店後などに「模擬営業」: レジ開局 → 予約作成 → 着席 → 注文 → 会計（現金とカード1件ずつ）
      → 返金1件 → レジ締め → 店舗日次締め → 日報 まで通す
- [ ] 数字が合っているか確認（レジ締めの理論現金と実現金）

---

## 前日

- [ ] 明日の予約一覧を確認（予約 → 本日/明日）
- [ ] 明日のシフトが入っているか（シフト）
- [ ] 在庫の重要品目に不足がないか（在庫 → 発注点割れ）
- [ ] 釣銭の準備（開始現金の額を決めておく。例: 各レジ3万円）
- [ ] 未処理のタスク・お知らせを確認

## 開店前（当日）

画面: レジ・小口現金 の「開店チェック」

- [ ] スタッフ出勤打刻
- [ ] レジ開局（**全レジ**。開始現金=数えた釣銭額を入力）
- [ ] 本日の予約組数を確認
- [ ] 売切にする商品があれば設定
- [ ] キッチンディスプレイ（KDS）を厨房の端末で表示

## 営業中

- [ ] 注文・会計は必ずTENPO ONEに通す（1件でも抜けると締めが合いません）
- [ ] 現金の入出金（両替・小口の出金）は必ずレジ画面から記録
- [ ] 返金するときは理由を入力。**商品の返品があった場合のみ「在庫に戻す」にチェック**
- [ ] 会計を取り消す場合は「取消（VOID）」、金額を戻す場合は「返金」を使い分ける
- [ ] 困ったら操作を止めて店長へ（データの削除・修正を勝手にしない）

## 閉店時

画面: レジ・小口現金

- [ ] 最終会計が終わっているか（未会計伝票の警告が0件）
- [ ] キッチンの未提供が残っていないか
- [ ] スタッフ全員の退勤打刻
- [ ] **各レジを締める**（実際に数えた現金を入力。差異が出たら理由を入力）
- [ ] **店舗日次締め**を実行（全レジ締め後。レジ別の内訳と店舗合計が表示されます）
- [ ] 現金差異があれば理由を確認（翌日に持ち越さない）
- [ ] 日報を生成し、店長コメントを書いて提出

## 翌日（本社・店長）

- [ ] 日報を本社が確認・承認
- [ ] ダッシュボードの昨日の売上・客数が体感と合っているか
- [ ] 経理: 照合ページ（経理 → 照合）で 売上照合✓・現金照合✓ を確認
- [ ] 経理: 自動仕訳（経理 → 仕訳 → 自動仕訳）で昨日分の売上・返金仕訳を確定
- [ ] 差異・違和感があれば当日中に原因を特定（時間が経つほど調査が難しくなります）

## 週次・月次（パイロット期間）

- [ ] 週1回: 廃棄の記録漏れがないか・在庫の実感と合っているか
- [ ] 週1回: 現金差異の傾向（毎回同じレジ・同じ時間帯なら運用を見直す）
- [ ] 月末: 棚卸を実施（理論在庫と実在庫の差を確定）
- [ ] 月末: 月次締め（経理）・給与の確定（**試算のまま。正式計算は専門家確認後**）
- [ ] 月次: 経営レポートで売上・原価・粗利・人件費・利益を確認

## 導入期間中にTENPO ONEでは「できない」こと（正直リスト）

| できないこと | 代替運用 |
|---|---|
| カード・QRの実決済処理 | 既存の決済端末で決済し、TENPO ONEには支払方法と金額を記録 |
| レシート・キッチン伝票の実機印刷 | 画面表示・手書き・既存プリンター併用 |
| キャッシュドロアの自動開放 | 手動 |
| 予約確認メール・LINE通知 | 電話・手動連絡 |
| グルメサイト予約の自動取込 | 手動で予約台帳へ入力 |
| 正式な所得税・社会保険計算 | 「試算」表示。正式計算は従来の方法/社労士と並行 |
| 銀行口座の自動連携 | 月次でCSVを取込 |

## トラブル時の連絡

- 画面がエラーになった: スクリーンショットを撮って時刻とともに報告
- 数字が合わない: **その日のうちに** 照合ページ（経理 → 照合）の結果とともに報告
- 絶対にしないこと: データの手動削除・二重入力によるつじつま合わせ
