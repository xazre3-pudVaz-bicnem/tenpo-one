## 実装方式

- ロール→アクションのマッピングを `lib/permissions.ts` に単一定義（`can(role, action)`）
- UI表示制御・Server Action内検証・Supabase RLS の3層で同じ定義を適用
- RLSはテーブル単位で「org一致 + 店舗スコープ + ロール条件」を関数化（`app_has_store_access` 等）
- 給与・個人情報はカラムレベルでビュー分離（本人明細は本人+許可ロールのみ）
