# レシートプリンター（Star mC-Print3）CloudPRNT 接続手順

FOGO 実店舗テスト向け。レシート実印字とキャッシュドロア開放を TENPO ONE から行うための設定。
**2026-08-27 に FOGO De BRASIA 新宿の実機（MCP31LB / MAC 00:11:62:50:a9:f3）で全経路を検証済み。**

## 方式：Star CloudPRNT（プリンタがサーバをポーリング）
- プリンタが TENPO ONE のHTTPSエンドポイントを定期的に見に行き、キューにある印刷ジョブ（レシート／ドロア）を取得・実行する。
- **店舗のLAN情報・固定IP登録は不要**。プリンタがインターネットに出られればOK。
- WebPRNT（ブラウザ→プリンタ直叩き）はHTTPSサイトからブロックされるため採用せず。

## 事前準備
- mC-Print3 をネットワーク接続（有線LAN推奨／Wi-Fi可）。電源・用紙・ドロア接続（RJ11でプリンタに接続）を確認。
- TENPO ONE の環境変数 `NEXT_PUBLIC_SITE_URL`（例 `https://www.tenpo-one.com`）が設定済みであること。
- **プリンタのIP設定が「動的（DHCP）」になっていること。** 中古機・移設機は前の設置場所の固定IPが
  残っていることがあり、その場合ゲートウェイが存在せずインターネットに出られない（下の「うまくいかないとき」参照）。

## TENPO ONE 側の設定
1. `設定 > レジ・プリンター` を開く。
2. 「プリンター」でレシート用プリンタが無ければ追加（用途=レシート、用紙幅=80mm、ドロアキック=必要ならON）。
   - 接続方式は表示用のメモ。CloudPRNTの動作には影響しない。
3. 「レシートプリンター（CloudPRNT）」パネルで対象プリンタの **「CloudPRNTを使う」をON**（即時保存される）。
4. 表示された **ポーリングURL**（`https://<サイト>/api/cloudprnt/<トークン>`）をコピー。**手打ちは不可**（トークン48文字）。
5. ポーリング間隔（既定5秒）を必要に応じて調整。

## プリンタ側の設定（mC-Print3 Web設定画面）
1. プリンタのIPにブラウザでアクセス（`http://<IP>`。ログインは初期値 `root` / `public`）。
   - IPが不明なら **FEEDボタンを押しながら電源ON** でセルフテスト印字にIPが出る。
2. 左メニュー **「クラウドプリント」**（※「スターマイクロニクスクラウド」は別物）。
3. **CloudPRNTサービス: 有効**。
4. **サーバーURL** に、コピーしたポーリングURLを貼付。
5. ポーリング間隔を TENPO ONE 側と合わせる（例 5秒）。
6. ユーザー名／パスワードは **空欄**（TENPO ONE 側はURLのトークンで認証しており、Basic認証は使わない）。
7. **Submit** → 左メニュー **「保存」** → 再起動。Submitだけでは確定しない。

## 動作確認
1. CloudPRNTパネルの表示が「未通信」→「最終通信 ○時○分」に変われば疎通OK。
2. **「テスト印刷」**。数秒後にレシートが出れば印字OK。
3. **「ドロアを開く」** でキャッシュドロアが物理的に開けば成功。
4. 実会計テスト：注文→会計→レシート画面の **「プリンタで印刷」**。現金会計時はドロア設定に従い自動でドロアが開く。

## 印字フォーマット（機種差の吸収）
mC-Print3 でもファームによって **Star Document Markup（`text/vnd.star.markup`）に非対応**の個体があり、
その場合プリンタは `510 Incompatible Media Type` を返して何も印字しない（FOGO新宿の実機がこれに該当）。

このため1つのジョブに Markup と **StarPRNT（`application/vnd.star.starprnt`）の両方の表現**を持たせ、
ポーリング応答の `mediaTypes` に列挙してプリンタ自身に選ばせている（`app/api/cloudprnt/[token]/route.ts`）。
新旧ファームが混在しても同じキューで動く。

StarPRNT 側の実機検証で確定した仕様（`lib/starprnt.ts`）:

| 項目 | 結果 |
|---|---|
| 文字エンコード | **CP932(Shift-JIS)**。UTF-8は英数字しか印字されず日本語が化ける |
| `¥`(U+00A5) | CP932に変換できない。**0x5C**（バックスラッシュ位置）で送ると ￥ として印字され、半角1桁のままなので桁揃えが崩れない |
| 整列 | `ESC GS a n`（0=左 / 1=中央）動作確認済み |
| 文字拡大 | `ESC i n1 n2` 動作確認済み |
| 強調 | `ESC E` / `ESC F` 動作確認済み |
| カット | `ESC d 3`（フィード＋部分カット） |
| ドロア | 1番=`BEL`(0x07) で開放を確認。2番=`SUB`(0x1A) |

プリンタ側に文字コード設定の項目は無い（Web設定画面はネットワーク設定のみ）。エンコードはサーバー側の責務。

## うまくいかないとき
- **プリンタが見つからない / 設定画面に繋がらない**：セルフテストのIPと、PCのIPのサブネットが一致しているか確認。
  一致していなければプリンタに**前の設置場所の固定IPが残っている**。同一L2上にはいるので、PCに一時的に
  そのサブネットのIPを追加すれば設定画面に入れる（例: `New-NetIPAddress -InterfaceIndex <n> -IPAddress 192.168.244.99 -PrefixLength 24`）。
  設定画面で **IPパラメータ → 動的（DHCP）** に変更・保存すれば正常なアドレスを取得する。作業後の一時IPは
  `Remove-NetIPAddress` で削除する。
- **レシートが出ない**：パネルの「最終通信」を見る。更新されていればポーリングは届いている＝ジョブ側の問題。
  `print_jobs` の `status` / `error` を確認（`510 Incompatible Media Type` なら形式、それ以外はプリンタ状態）。
  更新されていなければURL誤りかネット未接続。
- **英数字は出るが日本語が化ける**：StarPRNT のエンコードがUTF-8になっている。CP932で送る（実装済み）。
- **ドロアが開かない**：パネルの「ドロア開放コマンド」を `[drawer: 1]`→`[drawer: 2]` に変えて再試行（再デプロイ不要）。
  ドロアのRJ11が**プリンタ側**に挿さっているか、ドロアの鍵が開錠側かも確認する。
- **反映が遅い**：ポーリング間隔ぶんの遅延（最大 設定秒数）。短くすると即応性は上がるが通信は増える。

## 決済端末（stera pack）について
stera は TENPO ONE と電子連携していない。運用は「stera単体で決済 → TENPO ONE に『外部端末』として金額入力 → 会計確定」の手動2オペ（売上・レポートには正しく反映される）。自動連携はSMBC/GMO側の外部連携契約が前提。

## 技術メモ
- エンドポイント：`app/api/cloudprnt/[token]`（POST=ポーリング / GET=本文 / DELETE=確定）。トークンで店舗スコープ。
- GETの `Content-Type` はプリンタが `?type=` で要求した型をそのまま返し、`charset` 等のパラメータは付けない
  （厳密一致でしか受け付けないファーム対策）。
- ジョブ：`print_jobs`（target=cloudprnt, status queued→claimed→printed）。
  `payload.body` = Star Document Markup、`payload.starprnt` = StarPRNTバイト列のbase64。
- レンダラ：`lib/receipt-markup.ts` / `lib/starprnt.ts`。桁揃えは `lib/receipt-layout.ts` を共有し両形式で同じ見た目になる。
- 検証：`node --env-file=.env.local scripts/verify-cloudprnt.mjs [--http https://www.tenpo-one.com]`
- 実機デバッグの定石：プリンタと同一LANのPCでローカルCloudPRNTサーバーを立て、`mediaTypes` に候補を複数並べて
  プリンタがどれを `?type=` で要求するかを見ると、対応形式が一発で判明する。
