# レシートプリンター（Star mC-Print3）CloudPRNT 接続手順

FOGO 実店舗テスト向け。レシート実印字とキャッシュドロア開放を TENPO ONE から行うための設定。

## 方式：Star CloudPRNT（プリンタがサーバをポーリング）
- プリンタが TENPO ONE のHTTPSエンドポイントを定期的に見に行き、キューにある印刷ジョブ（レシート／ドロア）を取得・実行する。
- **店舗のLAN情報・固定IP登録は不要**。プリンタがインターネットに出られればOK。
- WebPRNT（ブラウザ→プリンタ直叩き）はHTTPSサイトからブロックされるため採用せず。

## 事前準備
- mC-Print3 をネットワーク接続（有線LAN推奨／Wi-Fi可）。電源・用紙・ドロア接続（RJ11でプリンタに接続）を確認。
- TENPO ONE の環境変数 `NEXT_PUBLIC_SITE_URL`（例 `https://www.tenpo-one.com`）が設定済みであること。

## TENPO ONE 側の設定
1. `設定 > レジ・プリンター` を開く。
2. 「プリンター」でレシート用プリンタが無ければ追加（用途=レシート、用紙幅=80mm、ドロアキック=必要ならON）。
3. 「レシートプリンター（CloudPRNT）」パネルで対象プリンタの **「CloudPRNTを使う」をON**。
4. 表示された **ポーリングURL**（`https://<サイト>/api/cloudprnt/<トークン>`）をコピー。
5. ポーリング間隔（既定5秒）を必要に応じて調整。

## プリンタ側の設定（mC-Print3 Web設定画面）
1. プリンタのIPにブラウザでアクセス（Star の設定ツール／Web Config）。
2. **CloudPRNT を有効化**。
3. **サーバURL** に、コピーしたポーリングURLを貼付。
4. ポーリング間隔を TENPO ONE 側と合わせる（例 5秒）。
5. 保存・再起動。

## 動作確認
1. TENPO ONE の CloudPRNT パネルで **「テスト印刷」**。数秒後にレシートが出れば疎通OK（「最終通信」時刻も更新される）。
2. **「ドロアを開く」** でキャッシュドロアが物理的に開けば成功。
3. 実会計テスト：注文→会計→レシート画面の **「プリンタで印刷」**。現金会計時はドロア設定に従い自動でドロアが開く。

## うまくいかないとき
- **レシートが出ない**：プリンタのCloudPRNTが有効か／サーバURLが正確か（末尾トークン含む）／ネット接続。パネルの「最終通信」が更新されていればポーリングは届いている＝ジョブ生成側を確認。
- **日本語が文字化け**：プリンタのCloudPRNT文字コード設定を **UTF-8** に。
- **ドロアが開かない**：機種によりドロア命令の方言が異なる。パネルの「ドロア開放コマンド」を `[drawer: 1]`→`[drawer: 2]` 等に変えて「ドロアを開く」で再試行（再デプロイ不要）。プリンタにドロアが正しく接続されているかも確認。
- **反映が遅い**：ポーリング間隔ぶんの遅延（最大 設定秒数）。短くすると即応性は上がるが通信は増える。

## 決済端末（stera pack）について
stera は TENPO ONE と電子連携していない。運用は「stera単体で決済 → TENPO ONE に『外部端末』として金額入力 → 会計確定」の手動2オペ（売上・レポートには正しく反映される）。自動連携はSMBC/GMO側の外部連携契約が前提。

## 技術メモ
- エンドポイント：`app/api/cloudprnt/[token]`（POST=ポーリング / GET=本文 / DELETE=確定）。トークンで店舗スコープ。
- ジョブ：`print_jobs`（target=cloudprnt, status queued→claimed→printed）。本文は Star Document Markup（`lib/receipt-markup.ts`）。
- 検証：`node --env-file=.env.local scripts/verify-cloudprnt.mjs [--http https://www.tenpo-one.com]`
