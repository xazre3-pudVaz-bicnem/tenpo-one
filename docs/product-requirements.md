# TENPO ONE — プロダクト要件定義

## サービス概要

- サービス名: **TENPO ONE**
- タグライン: 店舗運営を、ひとつに。 / One Platform. Every Store.
- 提供形態: マルチテナント型クラウドSaaS（飲食店向け）
- 運営: 株式会社サイプレス（CYPRESS）

飲食店が別々のサービスで運用している以下の業務を、**単一のデータベースと単一の操作画面**に統合する。

| 業務領域 | 置き換え対象の例 |
|---|---|
| オンライン予約・予約台帳 | 予約管理システム、紙の台帳 |
| POS・注文・会計 | タブレットPOS、レジスター |
| 売上・レジ締め・小口現金 | Excel日報、金庫ノート |
| 請求書・経費・書類管理 | ファイリング、会計ソフトの一部 |
| 勤怠・シフト | タイムカード、勤怠SaaS |
| 給与・歩合試算 | Excel給与計算 |
| CRM・顧客管理 | 会員カード、グルメサイト顧客情報 |
| 仕入・在庫 | 発注FAX、棚卸表 |
| レポート・経営分析 | 手作業の集計 |

## 最重要コンセプト：単一データでの連動

機能を横に並べるのではなく、**同じ organization_id / store_id / customer_id / order_id で全業務データが連鎖する**。

理想フロー（=MVPの縦の業務フロー）:

1. 客がオンライン予約 → `reservations` 作成
2. 予約台帳に自動表示 → テーブル割当（`reservation_tables`）
3. 来店・着席 → テーブル状態遷移
4. 予約から注文画面を開く → `orders` が `reservation_id` / `customer_id` を引き継ぐ
5. POSで注文・会計 → `order_items` / `payments`
6. 売上・支払方法別売上が自動記録
7. 現金会計はレジセッション残高（`cash_transactions`）へ反映
8. 顧客の来店回数・累計利用額が更新（`customers` 集計）
9. 商品販売数・在庫へ反映（`stock_movements`）
10. 担当スタッフ実績・歩合計算データへ反映
11. 日次・月次レポートへ即時反映
12. 本社が全店舗の業績を横断確認

**同じ内容を複数画面で再入力させない**ことを設計原則とする。

## ターゲット・ペルソナ

- **契約企業オーナー / 本社管理者**: 3〜50店舗を展開する飲食企業。店舗ごとにバラバラのツールと日報Excelに疲弊。全店の数字を朝一で見たい。
- **店長**: 予約台帳・レジ締め・シフト・発注を1台のiPadで済ませたい。新人にも教えやすいUIが必要。
- **ホールスタッフ / アルバイト**: 打刻・注文入力・会計だけを迷わず操作したい。
- **経理担当 / 外部税理士**: 店舗別の売上・小口現金・請求書を月次で確認し、CSVで会計ソフトへ連携したい。

## 参考サービスと差別化

SalonX（美容業界）の「予約・POS・CRM・給与が一つの顧客・売上データで連動する」思想を飲食店向けに再設計する。freee会計・KING OF TIME・レストランボード等は**解決している業務課題とワークフローのみ**を参考にし、UI・文言・データ構造・デザインはTENPO ONE独自とする。

飲食特化の独自要素:

- テーブル・フロア管理と予約台帳の一体化
- 店内/テイクアウトの税率（10%/8%）自動切替
- レジ締め・小口現金・釣銭準備金の現金一元管理
- 予約経路（自社/電話/グルメサイト等）別の分析
- アレルギー・記念日・接客メモをPOSと予約台帳の双方から参照

## 非機能要件

- 日本語UIを標準。文字列は `lib/i18n/ja.ts` に集約し将来の英語化に備える
- 金額は円単位の整数（浮動小数禁止）
- DBは timestamptz(UTC) 保存、表示は Asia/Tokyo
- PC=左サイドバー、スマホ=下部ナビ、タブレット=タッチ前提のPOS
- Lighthouse 90+、Core Web Vitals準拠（公開ページ）
- Supabase RLSによる企業間完全分離（フロント制御に依存しない）
- 重要データ（金額・勤怠・請求書・取消）は監査ログ必須、物理削除禁止

## 正直表示ポリシー

- 外部API連携（LINE・グルメサイト・会計ソフト・プリンターSDK）は、契約・認証情報・実機検証が完了するまで「対応済み」と表示しない
- 税務申告・法定給与計算（社保・源泉・年調）を代替できると表示しない。初期版は「試算」と明示
- OCRは結果を自動確定せず、人の確認を挟む
