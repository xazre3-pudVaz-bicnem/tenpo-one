# v0.4.3 REAL STORE PILOT HARDENING 完了報告

目標: **「実際の飲食店1店舗が、1日・1週間・1か月TENPO ONEだけで営業しても数字とデータが壊れない」**

検証手段: 専用テスト企業「[PILOT] TENPO ONE検証企業／新宿店」（レジ4台・15卓・スタッフ8名・
レシピ/直結在庫・営業17:00〜翌02:00・営業日境界05:00）で、1日・1週間・1か月の営業を
実RPC＋実RLSで再現し、**売上・現金・在庫・勤怠・給与・仕訳・利益を1円・1個・1分単位で照合**した。

## 2. 複数レジ仕様

- registers（レジ01/レジ02/テイクアウトレジ/モバイルPOS等）× register_sessions（開局〜締め）で
  レジごとに 開局状態・担当者・開始現金・現金売上/返金/入出金・理論現金・実現金・差異 を管理。
- /app/cash はレジをカード一覧表示し、複数レジの同時開局・個別締めに対応。

## 3. 店舗日次締め（2段階・migration 00027）

```
各レジ締め close_register_session（session単位・daily_closingsへは書かない）
   ↓ 全レジ締め後
店舗日次締め close_store_day（全レジ集約 → daily_closings確定）
```
- daily_closings に register_breakdown（レジ別内訳）・sessions_count を保存。店舗合計=各レジ合計。
- 未締めレジがあれば `OPEN_SESSIONS_REMAIN`（台数付き）で拒否。再オープンは理由必須+audit。
- 集約項目: 総売上/純売上/返金/支払方法別内訳（売上・返金別掲）/小口入出金/理論・実現金/差異/客数/客単価。
- 閉店前チェック（未会計伝票・未提供KDS・未退勤・未締めレジ・未処理小口）と開店チェックリストをUI化。

## 4. 支払方法別処理

- 支払方法: cash / credit / qr / emoney / voucher / on_account / points / **other（新規）**。
- 現金返金→レジ現金残高減、カード/QR/商品券等の返金→現金残高へ影響なし（cash_transactionsはcashのみ）。
- 混合支払（現金3,000+カード5,000+ポイント2,000等）: 返金ダイアログに**元支払の方法別内訳**
  （支払額/返金済み/残額）を表示し、選択方法の残額超過は警告。**配分は推測せずユーザーが確認して選ぶ**。

## 7. 1か月シミュレーション結果（scripts/verify-store-month.mjs）

**79/79 GREEN**。専用第2店舗（pilot-shinjuku-monthly）に約30日分の営業を生成し、月末処理を一周:

全日レジ/店舗締め → 勤怠確定 → 給与run（計算根拠breakdown・確定でrules_snapshot保存・
PAYROLL_RUN_LOCKED実証）→ 給与仕訳 → 売上/返金の日次自動仕訳30日分（冪等）→ 経費/仕入/小口仕訳 →

実原価（理論+廃棄+棚卸差異）→ 月次締め（DRAFT_ENTRIES_REMAIN→解消→成功→PERIOD_CLOSED）→
試算表（借方=貸方）→ P/L → B/S（資産=負債+純資産+当期純利益）。

月次経営レポート項目（売上/純売上/原価/粗利/粗利率/人件費/人件費率/FL/FL比率/経費/営業利益/
客数/客単価/廃棄/在庫差異）の恒等式を相互照合。

## 8-11. 照合結果（すべて1円・1個・1分単位で一致）

- **POS/会計**: POS売上（settled注文合計）= payments合計 = net_sales = 仕訳売上高 = P/L売上
- **現金**: 各レジ 開始+現金売上+入金−現金返金−小口出金 = 理論現金。店舗合計=レジ別合計（意図した差異も正しく検出）
- **在庫**: 開始在庫+入荷−販売使用(①直結+②レシピ)+返品戻し−廃棄±棚卸調整 = 現在庫（全品目）
- **勤怠/給与**: 出勤−休憩=実働。実働×時給+深夜+残業+歩合 = 給与試算（lib/payrollと独立再計算の一致・法定値は「試算」のまま）
- **仕訳/P&L**: 仕訳ベースP/L（売上/原価/人件費/経費/営業利益）とmetricsベース集計が一致

## 16. 残課題

1. 売切（is_sold_out）はQR注文RPCでのみDB強制。POSはUI制御のみ（スタッフの意図的販売を許す現仕様。DB強制するかはプロダクト判断）
2. 過去busines_dateを指定した遡及入力の管理者UI（現在は当営業日計上のみ）
3. 実原価の仕入価格変動はP/L恒等式と独立の参考指標（会計理論上正しい扱いだが、差異の完全分解には期首/期末棚卸評価の運用定着が必要）
4. 日報の自動生成トリガー（現在は手動生成。店舗日次締め後の自動生成は運用確認後）
5. パイロット企業の検証データはservice role以外から不可視だが、蓄積は続く（確定データは削除不可のため。定期的な企業ごと再作成で対応可能）
