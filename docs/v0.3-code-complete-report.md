## 1. v0.3で追加した機能

`CHANGELOG.md` v0.3.0節の詳細版。

- **会員・ポイント**: 付与率設定（例: 100円=1pt）・会計時自動付与・ポイント払い・返金時の比例取消/返還・履歴表示・手動調整。`loyalty_settings`/`point_transactions`、`customers.point_balance`/`member_no`
- **クーポンエンジン**: 固定額/%割引・対象商品/期間/時間帯（深夜跨ぎ対応）/利用回数/顧客あたり上限/新規顧客限定。POSでの適用、DB UNIQUE制約による二重適用防止
- **POS完成形**: 商品検索、おすすめ/売れ筋タブ、テンキー、クイック金額ボタン（1,000/5,000/10,000/ちょうど）、F2/F4/Escショートカット、顧客紐付け
- **レシートエンジン**（`lib/receipts.ts`）: 58mm/80mm切替、適格請求書番号、税率別内訳、QRコード、再発行/返金表示。`PrintProvider`抽象化（Browser実装／Mock失敗系テスト用／Epson・Starスケルトン）、ドロア抽象化（`shouldOpenDrawer`判定込み）
- **KDS**: 警告しきい値の店舗別設定、商品集約表示、音通知、ステーション別（キッチン/ドリンク）提供済み制御
- **予約**: `create_public_reservation`へのadvisory lockによるダブルブッキング競合排除、清掃バッファ設定、店頭ウェイティング（受付番号発行/呼出/案内→来店変換）
- **フロア**: 配置エディタ（座標・形状）、マップ描画
- **在庫**: 店舗間移動ワークフロー（申請→発送→受取、整合性RPC `ship_stock_transfer`/`receive_stock_transfer`）、負在庫許可設定、発注提案パネル（`lib/reorder.ts`）、曜日別需要予測（`lib/forecast.ts`）
- **CRM**: セグメント拡張（休眠30/60/90日、ランチ/ディナー/テイクアウト、誕生月等）、条件ビルダー（`campaignAudience`、URL永続化）、重複顧客候補検出+統合（監査付き`merge_customers` RPC）、顧客データ書き出し
- **経理**: 金額帯別承認ルール（自己承認禁止設定含む、`approval_rules`+`lib/approvals.ts`）、OCR受け皿（`DocumentExtractionProvider`、未接続を正直に表示するMock）、Inbox進捗・重複検知
- **労務**: 打刻状態機械の厳密化（`apply_punch` v2＝休憩中警告・二重出勤拒否・日跨ぎ自動確定）、給与確定期間ロック、シフト警告（連勤/週40h）、適用期間別給与ルール解決
- **経営**: 予算管理（達成率・線形着地予測）、日報（自動生成→提出→承認→検索）、店舗ランキング強化、異常検知閾値の設定化（企業既定+店舗override、`alert_rules`）
- **店舗運営**: タスク・引継ぎ、お知らせ（既読管理）、マニュアル管理
- **プラットフォーム**: グローバル検索+コマンドパレット（⌘K/Ctrl+K）、営業日境界設定（深夜営業対応、`app_business_date`）、PWAアイコン、オフラインバナー+POSガード、`/api/health`のadmin表示、セキュリティヘッダー、停止ユーザー即時遮断、レート制限層、CSVインポートウィザード、DB型生成（`lib/database.types.ts`）
- **運営コンソール**: サービス状態表示、利用量メータリング、subscription模擬管理、プラン上限、企業別機能フラグ
- **インフラ**: migration 00015〜00018、整合性CHECK制約/部分UNIQUE制約、実環境検証・E2Eテストの拡充

## 10. セキュリティ（headers/停止遮断/rate limit/ファイル検証/バンドル監査）

- **セキュリティヘッダー**（`next.config.ts`）: `X-Content-Type-Options: nosniff`、`Referrer-Policy`、`X-Frame-Options: SAMEORIGIN`、`Permissions-Policy`（camera/microphone/geolocation/payment拒否）、`Content-Security-Policy`（`frame-ancestors 'self'`のみ先行導入。完全なCSPはインラインスクリプトとの整合検証後に段階導入予定）、本番のみ`Strict-Transport-Security`
- **停止ユーザー即時遮断**: `requireSession`が`profiles.status === 'suspended'`を検出した時点でセッションを拒否（v0.2までは機能フラグ・権限チェックはあったが停止即時反映は未実装だった）
- **レート制限**: `lib/rate-limit.ts`（インメモリ・スライディングウィンドウ）。公開系（予約・QR注文・アップロード）に適用し、DBレベルの制限（`booking_request_logs`等）と二層防御。**単一プロセス内メモリのため、複数インスタンス構成では制限がインスタンスごとに独立する制約があり、本番でのマルチインスタンス運用時はRedis等への差替えを推奨**（`RateLimiter` interfaceは差替え前提で設計済み）
- **ファイル検証**: サーバー側で拡張子・サイズ（20MB上限）を検証（請求書添付・マニュアル添付）
- **バンドル秘密鍵監査**: `.next/static`に`service_role`キー・Stripe secret keyが含まれないことをリリースチェックリストでgrep確認する運用（v0.2から継続）
