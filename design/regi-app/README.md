# TENPO ONE レジ（iPad）画面設計 v2 — 実装用パッケージ

株式会社D&DREAM（Ronnie）から CYPRESS（小田さん）への **レジ画面（iPad）の新レイアウト設計** です。
全店舗共通のレジ画面として、コードレベル（Next.js 本体）で実装をお願いします。管理画面（ダッシュボード／予約／仕入／経理…）は別物で、この設計の対象外です。

## 見方
1. `tenpo-one-regi.html` を開く → ログイン画面が出た場合は担当者を選び、暗証番号は任意の4桁。
2. サイドバー: オーダー・会計 ／ 店舗台帳 ／ ホーム ／ 即会計 ／ 伝票明細 ／ 入出金 ／ 仕入・経費 ／ 両替 ／ 在庫設定 ／ レジクローズ ／ スキャン ／ 設定 ／ アラート。
3. 注文の流れ: テーブル一覧 → 空席タップ → お客様情報 → 注文（左カテゴリ／中央メニュー／下ファンクションバー／右伝票）→ 会計（割引・割り勘・領収書・現金テンキー）→ 会計確定で伝票化・空席化。
4. デモ操作: スケジュールの予約バーはドラッグで時間（横）・テーブル（縦）を変更。スキャン画面の「デモ用サンプル」で AI 読み取り→自動修正→自動登録の流れが見られます。

## 実装の優先順位（提案）
1. **注文・会計**（現行 `/app/pos` の置き換え、全店舗共通）: テーブル一覧カード、お客様情報、注文画面、会計、伝票明細、即会計、席移動・連結・合算
2. **ホーム／入出金／レジクローズ**: 今日のやること、予算達成率、入出金（📷レシート・仮払い→精算）、出金レシートチェック付きクローズ
3. **店舗台帳**: 予約リスト／スケジュール（ドラッグ）／月間／顧客台帳／直接来店／空席検索／印刷・PDF
4. **仕入・経費／スキャン**: 未払・支払／納品書照合／月次決算／取引先／レシートボックス／MF取込CSV（AI-OCR は後続フェーズ）
5. **設定**: デバイス管理（ハードウェア・テーブルQR・ハンディQR）／グルメサイト連携／会計ソフト連携／本部 全店舗ビュー

## 既存コードとの対応（目安）
- `components/pos/pos-screen.tsx` → 注文画面（左カテゴリレール `#cats` ／ 商品グリッド `#items` ／ 伝票 `#cart` ／ ファンクションバー）
- `app/app/pos/print-actions.ts`（レシート・ドロア）＋ `feat(printing): キッチン伝票`（ae0e8f8）→ ファンクションバー「キッチンへ送信」= キッチン伝票の enqueue、会計確定 = レシート印刷＋ドロア
- `app/app/settings/printers`（CloudPRNT）→ 設定 › デバイス管理 › ハードウェア
- `app/app/settings/tables`（QR）→ 設定 › テーブルQRコード（モバイルオーダー `app/order/[storeSlug]/[tableToken]`）
- `app/app/settings/clerks`（POS担当者）→ ログイン画面の担当者選択・トップバーの担当チップ
- データモデルは `DD-REGI_spec_v32.md` 第4章（TABLES / ORDERS / RESV / CUSTOMERS / SLIPS / CASH / VENDORS / BILLS / DELIV / SCANS …）を Supabase のテーブル設計に流用してください。既存テーブル（orders・tables・print_jobs・printer_configs・pos_clerks 等）との対応は要相談。

## デザイン・トークン
- 配色は HTML 先頭 `<style>` の `:root` に集約（`--plum` トップバー／`--iris` プライマリ紫／`--lilac` 背景／`--saffron` 金額／`--good`・`--alert`）。tenpo-one 配色版に切り替える場合は同じトークンの値だけ差し替え。
- フォント: Noto Sans JP（数字は tabular-nums）。ラベルは日本語＋小さな英語サブラベル（`.en-inline` / `<small class="en">`）。
- テーブルカードの状態色: 着席=薄紫／注文済=紫／L.O.済=黄／時間超過=赤／会計待ち=橙／空席=破線。下端の線＝残り時間。
- CSS 接頭辞: 共通クローム `a-`（`.a-top .a-side .a-item …`）、注文画面 `ao-`（`.ao-rail .ao-grid .ao-fbar .ao-slip …`）。それ以外は B 由来のクラス。

## モックである部分（本番で置き換え）
永続化（メモリ→DB）、複数端末同期、AI読み取り（サンプル値→OCR API）、プリンター／ドロア／決済端末／ハンディ／QR注文（表示のみ→ePOS/WebPRNT・決済API）、グルメサイト・MF/freee・本部連携（トースト→API）、`window.print()`。詳細は仕様書 第7章。
